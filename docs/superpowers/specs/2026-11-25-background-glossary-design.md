# 翻译背景：提炼摘要 + 术语表 — 设计

日期：2026-11-25 · 状态：待批准（第二版，按评审意见修订）

## 意图

实时字幕里专有名词、人名经常译错或同一场里前后不一致（Hermione 一会儿「赫敏」一会儿「赫米恩」）。用户希望在开始前给一段「这次在听什么」的背景，由插件准备两样东西：

1. **术语表**：原文=译文 的词条，翻译时参照；
2. **背景摘要**：LLM 把背景提炼成几句短话，也进入 prompt，让模型知道在聊什么、谁是谁，从而译得更准。

对话中已确认：准备方式为方案 A（模型生成 → 可看可改 → 注入）；背景摘要可编辑；开启重开 DSH 后仍保留。

第二版修订（评审意见）：

- 术语表可能很长（一部电影几十到上百条），配置页要做折叠/滚动/计数的友好设计；同时**每句只注入与本句相关的词条**，避免 prompt 随词表线性膨胀。
- 背景经提炼后**也要进 prompt**（上一版只进词表，不进摘要）。

## 目标

- 控制页输入背景（自由文本），点「准备词汇」→ 一次模型调用同时产出**摘要**和**术语表**。
- 摘要与术语表都可见、可改、可清空；播放中修改下一句生效，不重启采集。
- 词表很长时页面不撑爆：默认折叠、展开后固定高度内滚动、显示条数与字符数、清空需二次确认。
- 准备失败或没产出时保留旧内容，在面板说明，不影响播放。
- 重开 DSH 后背景、摘要、术语表都在。

## 非目标

- 不恢复片名库、`/rt title`、`media.glossary` 或任何"按片名查文件"的机制。
- 不联网查资料；背景只来自用户输入（模型可以用自身知识补充与翻译相关的设定，但不得编造确定不了的细节，见"提炼 prompt"）。
- 不做多套背景预设/切换，不加 `/rt bg` 命令（列为后续）。
- 不改字幕渲染、音频链路、分段器。

## 约束

- 翻译是一句一次流式请求。摘要短（≤ 300 字符）且稳定，固定注入；**术语表按句过滤后注入**，每句最多 12 条。
- 准备是额外一次 LLM 调用（几秒），用与翻译相同的 provider/model 路由；失败不能挡住播放。
- 词表存储上限 200 行 × 120 字符，清洗上限 80 条，模型侧要求最多 60 条；这些上限只写在 `src/ui.ts` 的校验函数里。
- 浏览器半（`client.js`）无构建、无 JSX、只能 `require('react')`；`tests/client.test.ts` 的 React stub 只有 `useState/useEffect/useRef/useCallback`，不要引入新 hook。
- Host 代码有 ESM 缓存，验证必须完全退出 DSH 重开；只改 `client.js` 时刷新页面即可。
- 背景、摘要、词表会发给用户自己的 LLM，并写入 profile；不新增音频落盘或云端 ASR。

## 方案

- **A. 背景 → 一次模型调用 →（摘要 + 可编辑词表）→ 摘要每句注入、词条按句过滤注入。** 选定。
- B. 背景原文每句拼进 prompt：零准备、不会失败，但每句 prompt 变长（2000 字背景 × 每句），术语每句重猜，不可见不可改。
- C. 纯手填摘要与词表、不调模型：编辑框空着时天然就是 C，作为保底。

选 A。相对上一版的两点变化都是 A 内部的改进：把提炼结果做厚（摘要），把注入做薄（按句过滤）。

## 设计

### 数据（config / profile）

- `translate.background: string`（新增，原始输入，默认 `''`，≤ 2000 字符）
- `translate.backgroundBrief: string`（新增，提炼后的摘要，默认 `''`，≤ 300 字符，可手改）
- `translate.glossary: string[]`（已有，每行一条；上限 200 行 × 120 字符）
- `translate.glossaryError: string | null`（运行时提示，不进 profile，成功时清空）
- 全部经 `patchSettings` 写 profile，面板从快照读。

### 准备流程（按钮触发）

1. 面板先提交当前背景（失焦提交；点「准备词汇」前也提交一次）。
2. `prepareGlossary` 动作：背景为空 → 只记 `glossaryError = '先填写翻译背景'`，不调用模型。
3. `Translator.prepareGlossary()` 用 `route()` 的同一个 provider/model，一次调用（`temperature: 0.2`、`maxTokens: 2000`、60s 超时），要求按固定格式输出：

   ```text
   [摘要]
   <不超过 3 句话、120 字以内：在讨论什么、涉及哪些人/作品/概念、语气场景>

   [术语]
   Hermione=赫敏
   Quidditch=魁地奇
   ```

   prompt 明确：只输出与翻译有关的摘要和词条，不要编号、解释、Markdown；词条最多 60 条；背景只提到作品名时，可结合你对该作品的了解补充关键人物与设定，不确定的不要编。
4. `parseModelPrep(text)` 解析：优先找 `[摘要]` / `[术语]` 标记（也容忍 `摘要：`、`术语：`）；标记缺失时退化处理——第一个非空段落作摘要，含 `=` 的行作词条。摘要压成一行、≤ 300 字符；词条走下面的清洗。
5. 词条清洗：去代码块围栏、列表符号（`-`、`*`、`1.`、`1)`）、空行；只保留含 `=` 的行；按第一个 `=` 拆分并 trim；按原文小写去重；上限 80 条。
6. 摘要非空或词条非空 → 写回对应字段（空的那项保留旧值），清空 `glossaryError`。两项都空 → 保留旧值，`glossaryError = '未生成内容，可手填或换个说法'`。
7. 抛错/超时 → 保留旧值，`glossaryError` 记错误信息；不向播放路径传播。
8. 播放中修改任一字段：pipeline 每段重读 `settings`，下一句即生效，不重启采集。

### 注入 prompt（`buildPrompt`）

```text
[Background]
<backgroundBrief>

[Glossary]
<本句命中、最多 12 条>

[Recent context]
原文: … / 译文: …

[Current]
<sentence>
```

- 新增 `selectGlossary(text, entries, limit = 12)`：按原文小写子串匹配（CJK 同样有效），命中才注入；`原文=译文` 取 `=` 左边，纯词条整行匹配；去重后按出现顺序，超限截断。
- `TranslateRequest` 加 `brief`；`glossary` 仍是完整列表，由 `buildPrompt` 内部过滤。调用点（`pipeline`、`controller.test()`）只多传一个 `brief`。
- 没有摘要/没有命中词条时省略对应段（沿用现有"不留空段"约定）。

### 面板动作（`PANEL_ACTIONS` 新增四个）

- `setBackground`：string，trim，≤ 2000 字符。
- `setBrief`：string，压成一行，≤ 300 字符。
- `setGlossary`：string[] 或换行字符串；逐行 trim、去空、去重、≤ 200 行 × 120 字符；不强制 `=`。
- `prepareGlossary`：无 value，按上面的流程准备。

`ActionName`、`PANEL_ACTIONS` 增加这四项；不改 overlay 的 `ACTIONS`。

### 快照

`translate` 扩为 `{ provider, model, background, backgroundBrief, glossary, glossaryError }`。

### 控制页（「语言」卡之后）

折叠态（默认，词表 > 8 条时）：

```text
┌ 翻译背景（可选） ────────────────────────────────────┐
│ 看《哈利·波特与魔法石》，聊魁地奇和学院杯…             │
│ [准备词汇]  用当前翻译模型提炼背景并生成词表            │
│ 摘要 · 52 字                                      [改] │
│ 术语 87 条 · 约 1.1k 字符                     [展开] [清空]│
└─────────────────────────────────────────────────────┘
```

展开态：

```text
┌ 翻译背景（可选） ────────────────────────────────────┐
│ 看《哈利·波特与魔法石》，聊魁地奇和学院杯…             │
│ [准备词汇]  用当前翻译模型提炼背景并生成词表            │
│ 背景摘要（会进 prompt）                              │
│ ┌────────────────────────────────────────────────┐  │
│ │ 哈利·波特与魔法石观影场景：魔法学校一年级，涉及…    │  │  ← 3 行，滚动
│ └────────────────────────────────────────────────┘  │
│ 术语 87 条 · 约 1.1k 字符                 [收起] [清空]│
│ ┌────────────────────────────────────────────────┐  │
│ │ Hermione=赫敏                                   │  │  ← 高 240px，内部滚动，等宽
│ │ Quidditch=魁地奇                                │  │
│ │ …（87 行）                                      │  │
│ └────────────────────────────────────────────────┘  │
│ 每行一条「原文=译文」；翻译时只注入本句出现的词条（≤12 条）│
│ 上次准备：未生成内容，可手填或换个说法                  │
└─────────────────────────────────────────────────────┘
```

- 两个 textarea 各自 `useState`，失焦时 `act('setBackground'|'setBrief'|'setGlossary', …)`；轮询只在**未聚焦且无未提交改动**时用快照回填，避免 1.5s 轮询覆盖正在打的字。
- 词表默认折叠，头部显示条数与字符数；展开后固定高度滚动，页面高度不变。空表显示「暂无术语，可手填」。
- 「清空术语」两步确认（第一次点击变成「确认清空？」，3 秒后复原）；只清术语，不碰背景与摘要。
- 「准备词汇」在背景为空或请求进行中禁用，进行中显示「准备中…」。
- `glossaryError` 显示在卡片底部，不弹窗。

## 验证

自动：

```powershell
npm test
npm run test:overlay   # 未改 overlay，应无回归
```

手动（Host 有改动，必须完全退出 DSH 后重开）：

1. 打开「实时翻译」页，输入《哈利·波特与魔法石》类背景，点「准备词汇」：出现摘要与几十条术语；摘要能改，改完立即保存。
2. 词表超过 8 条时默认折叠；点「展开」后卡片高度不涨、内部可滚动；「清空术语」点一次变「确认清空？」，再点才清。
3. 播放对应音频：Hermione 类人名按词表译出；把某条改掉，下一句即用新译名，不重启、不断流。
4. 播放一段与本背景无关的音频：术语几乎不命中，译文不应被硬塞词条（用日志或对照确认注入条数变少）。
5. 清空背景后「准备词汇」禁用；制造一次失败（如临时把模型路由指到不可用），旧摘要/旧表保留且显示错误，播放不受影响。
6. 完全退出 DSH 再开：背景、摘要、术语表仍在。

## 留给实现者

- 提炼 prompt 的措辞、模型条数上限（60）与解析上限（80）可按实测微调；"只输出摘要与词条"的格式不能丢。
- 「摘要」是否参与准备按钮的禁用判断：默认只看背景。
- 每句注入上限 12 可调；若实测长句命中过多，优先保证人名词条。
- 后续（不在本轮）：`/rt bg <text>`、`/rt glossary`、多套背景切换、术语表导入导出。

## 2026-11-26 修订：空背景与提示位置

- 背景为空时按钮不再禁用：点击后只在按钮右侧提示「先填写翻译背景，再点「提炼背景并生成词表」」，不调用模型（宿主仍保留空背景拒绝对话，见 `Controller.prepareGlossary`）。
- `glossaryError` 已从卡片底部移到「提炼背景并生成词表」按钮右侧同一行（2026-11-25 调整）。
- 重新点击提炼时，面板先隐藏上一次的 `glossaryError`，再按本次校验/提炼结果重新显示；不会等模型调用结束才消失。
