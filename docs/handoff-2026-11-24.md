# 2026-11-24 工作交接：多行历史字幕

## 本次需求

在已完成“控制条入窗 / 会议默认双语 / 译文不被下一句原文顶掉”的基础上，新增：

> 支持显示多行（2~5 行）的原文字和翻译文字，最后一行为当前正在说话的，前面几行为最近几句话的历史。

## 实现方式

### 行模型

- `subtitle.maxLines` 现在表示**句子行数（2~5）**：最后一行为当前正在说的话，上方为最近几句历史。
- 每行显示「小字原文 + 大字译文」；历史行不透明度 0.7，当前行 1.0。
- 新句子从底部进入；超过行数后最旧的一行滚出。
- 译文刚出现时，即便下一句已经开始，也会多保留一行，直到 `minReadMs` 满足才允许滚出。
- `holdMs` 改为“静音清屏”：最新一行超过 `holdMs` 没有更新时，清空全部行。

### 配置变化

- `subtitle.maxLines`：2–5，会议默认 3、影视默认 4。
- `subtitle.minReadMs`：译文最短可读时间，会议 1800 ms、影视 1500 ms。
- `subtitle.holdMs`：静音清空时间，均为 6000 ms。
- 移除 `subtitle.display`（`primary` / `all`）——多行窗口取代了原来的单行/多行切换。
- 控制条「行数」改为「行数（句）」，范围 2–5。

### 代码改动

- `src/config.ts`：预设置调整、移除 `display`、`maxLines` 2–5。
- `src/subtitle/protocol.ts`：`StylePayload` 移除 `display`。
- `src/controller.ts`、`src/index.ts`：`SubtitleModel.maxCues = max(3, maxLines + 1)`，为历史行和当前句留位置。
- `src/ui.ts`：`maxLines` 钳制到 2–5，移除 `display` 补丁。
- `assets/overlay/overlay.ps1`：
  - 用 `Select-VisibleCues` 取代 `Select-DisplayedCue`：滚动窗口 + `minReadMs` 保留一行 + 当前句在最后；
  - `Render-Cues` 按行渲染并给历史行降透明度；
  - `Remove-IdleCues` / `Expire-Cues` 只做静音清屏，不再按单条年龄逐条删除；
  - `-SelfTestRows` 纯状态机自检（9 个断言，不弹窗），`-SelfTestHold` 保留为别名。
- `client.js`：行数步进器改为 2–5，标签「行数（句）」。
- 测试：config / controller / protocol / ui / overlay-restart 更新；`npm test` 74/74。

## 2026-11-24 追加：控制条 405 修复

现象：右下角控制条显示「实时翻译 未连接 / transport failure for /rt-translation/state: HTTP 405」。

诊断过程：

- 直接请求 `POST /rt-translation/state` 返回 `405 Allow: GET, HEAD`；对任意未注册路径做 POST 也是同样结果（SPA 静态兜底只接受 GET/HEAD），说明该路由**根本没有注册**。
- 原实现通过 `ctx.connection.rpc.handle('/rt-translation', ...)` 注册自定义 RPC 通道；在 Desktop Host 中没有生效（路由不存在，而不是鉴权失败）。
- 同机 `@nanmicoder/dsh-agent-teams` 验证过的做法是：直接在 `webServer` 上注册 exact 路由（`/plugins/dsh-agent-teams/state`），浏览器同源 `fetch`，认证用 `connection.requestRejection(req)`。本机该插件的路由可用。

修复：

- `src/panel.ts` 改为 `registerPanelRoutes(webServer, connection, deps)`：
  - `GET /plugins/dsh-rt-translation/state` 返回面板快照；
  - `POST /plugins/dsh-rt-translation/action` 接收 `{ action, value }`，复用 `dispatchAction`；
  - 认证在请求时通过 `connection.requestRejection(req)` 完成；请求体限 64 KB；
  - 非法方法 405、非法动作 400、未授权 401/403、Connection 未就绪 503。
- `src/index.ts` 用 `ctx.get('webServer')` 懒注册，并监听 `internal/service` 事件在 `webServer`/`connection` 晚绑定时重试（与 agent-teams 一致）。
- `client.js` 改为同源 `fetch` 上述两个路径，401/403/503 显示中文提示；不再依赖 `connection.rpc`。
- 新增 `tests/panel.test.ts`：路由注册、state 快照、action 分发、401/405/400；`npm test` 77/77。

注意：

- **Host 插件代码有 ESM 模块缓存**：在插件页停用/启用只会重新执行旧模块（调试日志确认新代码未加载），验证本次修复必须**完全退出 DSH 后重新打开**。
- 停用/启用还可能残留旧的 overlay 进程（当前观察到两个）；重启会清理。
- 临时诊断日志写入 `%TEMP%\dsh-rt-translation.log`（每次 apply 一行），验证通过后可删除该调试代码。

## 2026-11-24 追加：托盘“退出”后可再次开始

问题：托盘右键「退出」调用的是 `controller.dispose()`，会把控制器永久标记为已释放并销毁 renderer，之后 DSH 控制条和 `/rt start` 都无法再启动。

修复：

- `WindowsWpfRenderer` 新增 `close()`：关闭 overlay/托盘进程但不置 `disposed`，之后 `start()` 可重新拉起；`dispose()` 仍是不可恢复的最终释放。
- `Controller.start()` 在准备识别前先 `renderer.start()`，overlay 被关闭后会重新生成（样式与 UI 配置在 spawn 时自动重发）。
- 托盘「退出」动作改为 `controller.quit()`：停止采集、关闭 overlay/托盘，但保留插件可再次启动；下次开始会重新出现托盘和字幕窗。
- 新增测试：`close` 后 `start` 可再拉起、`dispose` 后不可；控制器“退出后仍可再次开始并重新拉起字幕窗”。`npm test` 79/79。
