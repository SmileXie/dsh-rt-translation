## 本次需求

在已完成“控制条入窗 / 会议默认双语 / 译文不被下一句原文顶掉”的基础上，新增：

> 支持显示多行（2~5 行）的原文字和翻译文字，最后一行为当前正在说话的，前面几行为最近几句话的历史。

## 实现方式

### 行模型

- `subtitle.maxLines` 现在表示**句子行数（2~5）**：最后一行为当前正在说的话，上方为最近几句历史。
- 每行显示「小字原文 + 大字译文」；历史行不透明度 0.7，当前行 1.0。
- 新句子从底部进入；超过行数后最旧的一行滚出。
- 译文刚出现时，即便下一句已经开始，也会多保留一行，直到 `minReadMs` 满足才允许滚出。
- `holdMs` 改为“静音清屏”：最新一行超过 `holdMs` 没有更新时，清空全部行。

### 配置变化

- `subtitle.maxLines`：2–5，会议默认 3、影视默认 4。
- `subtitle.minReadMs`：译文最短可读时间，会议 1800 ms、影视 1500 ms。
- `subtitle.holdMs`：静音清空时间，均为 6000 ms。
- 移除 `subtitle.display`（`primary` / `all`）——多行窗口取代了原来的单行/多行切换。
- 控制条「行数」改为「行数（句）」，范围 2–5。

### 代码改动

- `src/config.ts`：预设置调整、移除 `display`、`maxLines` 2–5。
- `src/subtitle/protocol.ts`：`StylePayload` 移除 `display`。
- `src/controller.ts`、`src/index.ts`：`SubtitleModel.maxCues = max(3, maxLines + 1)`，为历史行和当前句留位置。
- `src/ui.ts`：`maxLines` 钳制到 2–5，移除 `display` 补丁。
- `assets/overlay/overlay.ps1`：
  - 用 `Select-VisibleCues` 取代 `Select-DisplayedCue`：滚动窗口 + `minReadMs` 保留一行 + 当前句在最后；
  - `Render-Cues` 按行渲染并给历史行降透明度；
  - `Remove-IdleCues` / `Expire-Cues` 只做静音清屏，不再按单条年龄逐条删除；
  - `-SelfTestRows` 纯状态机自检（9 个断言，不弹窗），`-SelfTestHold` 保留为别名。
- `client.js`：行数步进器改为 2–5，标签「行数（句）」。

## 2026-11-24 追加：控制条 405 修复

现象：右下角控制条显示「实时翻译 未连接 / transport failure for /rt-translation/state: HTTP 405」。

诊断过程：

- 直接请求 `POST /rt-translation/state` 返回 `405 Allow: GET, HEAD`；对任意未注册路径做 POST 也是同样结果（SPA 静态兜底只接受 GET/HEAD），说明该路由**根本没有注册**。
- 原实现通过 `ctx.connection.rpc.handle('/rt-translation', ...)` 注册自定义 RPC 通道；在 Desktop Host 中没有生效（路由不存在，而不是鉴权失败）。
- 同机 `@nanmicoder/dsh-agent-teams` 验证过的做法是：直接在 `webServer` 上注册 exact 路由（`/plugins/dsh-agent-teams/state`），浏览器同源 `fetch`，认证用 `connection.requestRejection(req)`。本机该插件的路由可用。

修复：

- `src/panel.ts` 改为 `registerPanelRoutes(webServer, connection, deps)`：
  - `GET /plugins/dsh-rt-translation/state` 返回面板快照；
  - `POST /plugins/dsh-rt-translation/action` 接收 `{ action, value }`，复用 `dispatchAction`；
  - 认证在请求时通过 `connection.requestRejection(req)` 完成；请求体限 64 KB；
  - 非法方法 405、非法动作 400、未授权 401/403、Connection 未就绪 503。
- `src/index.ts` 用 `ctx.get('webServer')` 懒注册，并监听 `internal/service` 事件在 `webServer`/`connection` 晚绑定时重试（与 agent-teams 一致）。
- `client.js` 改为同源 `fetch` 上述两个路径，401/403/503 显示中文提示；不再依赖 `connection.rpc`。
- 新增 `tests/panel.test.ts`：路由注册、state 快照、action 分发、401/405/400；`npm test` 77/77。

注意：

- **Host 插件代码有 ESM 模块缓存**：在插件页停用/启用只会重新执行旧模块（调试日志确认新代码未加载），验证本次修复必须**完全退出 DSH 后重新打开**。

## 2026-11-25 追加：修复「一句话只识别到前半句/后半句」

现象：播放会议语音时，原文经常只剩一句话的前半截或后半截，译文也跟着残缺。

诊断（先证据、后改动）：

- `%TEMP%\dsh-rt-translation.log` 中 `drop stale segment` / `stt failed` / `translation failed` 计数全为 0：识别队列没有丢段，问题不在排队或识别失败。
- 运行中的 profile `C:\Users\admin\.dsh\profiles\desktop\cordis.patch.yml` 里 `segment.silenceMs: 150`。150 ms 小于正常换气/分句停顿（约 300–500 ms），等于每个停顿都判成一句结束。用合成会议语句（两个分句 + 400 ms 停顿 + 句尾渐弱）实测：150 ms 切成 2 段，550 ms 合成 1 段。
- `src/audio/vad.ts` 的 `finalize()` 把音频裁到「最后一个超过起段门限的帧 + 100 ms」。会议里句尾降调、语气词常比句首低十几 dB，会被当成静音整块丢掉（实验：2 s 语音 + 300 ms 轻声尾音，只送 105 帧，尾音全丢）；句首同理，旧 pre-roll 200 ms 只能兜住 260 ms。
- 起段/断段共用同一个门限，且噪声底在语音帧上也会更新：一句话的头几个音节会抬高本次语音期间的门限，句中轻声字被判成静音、切成两半。

修复：

- `src/audio/vad.ts`：`finalize()` 保留整段音频（含句尾轻声）；起段门限 `max(噪声底*2.5, 320)`、断段门限 `min(max(噪声底*1.5,140), 起段*0.7)` 形成滞回；噪声底只在 idle 且低于起段门限时更新；pre-roll 默认 400 ms；强制切分窗口 1500→2500 ms；最短有效语音按「超过断段门限的帧数」判断。
- `src/config.ts`：`silenceMs` 280→550、`maxSegmentMs` 5000→8000、`preRollMs` 200→400。
- `client.js`：面板兜底值同步；分段设置下加一行提示「静音切分越短越灵敏，但短于正常停顿会把一句话切成两半；会议语音建议 500–800 ms」。
- 本机 profile 的 `segment` 改为 `silenceMs: 550`、`preRollMs: 400`（`maxSegmentMs` 保留用户的 10000）。

已验证：

- `npm test`：**84/84 通过**（新增 5 个 VAD 回归用例：句尾轻声、句首轻声、句中轻声字、550 ms 内停顿不切句、超阈值停顿仍切句）。
- `npm run test:overlay`：9/9 PASS，无回归。
- 合成音频对比：一句会议话（400 ms 分句停顿）150 ms→2 段、550/600 ms→1 段；12 s 连续讲话 max 5000→4 段、max 8000→2 段。

## 2026-11-25 追加：修复多显示器拖动后字幕跳回主屏

现象：把字幕窗拖到副屏后，只要出现新字幕（`Render-Cues` → `Position-SubtitleWindow`），窗口就跳回主屏。

根因（已复现）：`Position-SubtitleWindow` 用 `[System.Windows.SystemParameters]::WorkArea` 做位置钳制，而它只返回**主显示器**的工作区。本机主屏 1920 宽、副屏从 x=1920 开始；拖到副屏后 `Left≈2500`，钳制条件 `Left + width > WorkArea.Right` 成立，`Left` 被改写成 `1920 - 1498 = 422`，窗口横跨回主屏。副屏在上方/下方时同样会被主轴或底边钳制。另一个隐患：`DragMove()` 的嵌套消息循环里 stdin 定时器仍会触发新的 cue，拖动过程中窗口可能被重新定位。

修复：

- 拖动结束后的坐标**原样保留**，不再按主屏工作区钳制；只把「尚未拖动」的初始位置继续放在主屏底部居中。纯数学抽到 `Resolve-SubtitlePlacement`，非法坐标（NaN/Infinity）回退默认位置。
- 新增 `$script:dragging`：`MouseLeftButtonDown` 进入 `DragMove` 前置位，拖动期间 `Position-SubtitleWindow` 直接返回，避免和新字幕抢位置；拖完在 `finally` 中记录 `Left/Top`。
- 新增 `overlay.ps1 -SelfTestPosition`（5 条断言，不弹窗）：右侧副屏、负坐标副屏、副屏下缘不被主屏钳制、初始底部居中、非法坐标回退。`npm run test:overlay` 现在串联行窗口与位置两套自检。

验证：

- `overlay.ps1 -SelfTestPosition` 5/5，`-SelfTestRows` 9/9，`-SelfTestIcon` 1/1。
- `npm test` 91/91（本机沙箱内 `node --test` 默认按文件 spawn 会 EPERM，本次用 `node --test --test-isolation=none "tests/**/*.test.ts"` 等价运行）。
- 真机多屏拖动仍需人工确认：拖到副屏后继续出字幕，窗口应留在副屏。

注意：改的是 overlay 脚本，需**完全退出 DSH 再重开**让旧的 overlay 进程重新加载脚本。

## 2026-11-25 追加：翻译背景（提炼摘要 + 术语表）

需求：开始翻译前给一段「这次在听什么」的背景（如「看《哈利·波特与魔法石》」），由插件准备术语，翻译时参考；背景经提炼后也要进 prompt。术语表可能很长，配置页要能折叠/滚动；每句只注入与本句相关的词条，避免 prompt 随词表线性膨胀。

设计（全文见 [`docs/superpowers/specs/2026-11-25-background-glossary-design.md`](superpowers/specs/2026-11-25-background-glossary-design.md)，实施计划见 [`docs/superpowers/plans/2026-11-25-background-brief-glossary.md`](superpowers/plans/2026-11-25-background-brief-glossary.md)）：

- 「提炼背景并生成词表」一次 LLM 调用（与翻译同一 provider/model，30–60s 超时）同时产出 `[摘要]` 与 `[术语]`；两者都写 profile（`translate.background` / `backgroundBrief` / `glossary`），所以重开 DSH 不丢，代价是上一场背景会留着（面板可见、可清空）。
- prompt 顺序：`[Background]`（摘要，≤300 字符）→ `[Glossary]`（本句命中，≤12 条）→ `[Recent context]` → `[Current]`；任一为空整段省略。词条按大小写不敏感子串匹配本句原文。
- 模型输出解析做了退化处理：无标记、CRLF、代码围栏、`-`/`1.` 列表都能收；摘要压成一行；词条按 `原文=译文` 去重，上限 80；空结果不覆盖旧值。
- 失败语义：背景为空不调模型；失败/超时/空结果都保留旧摘要与旧表，只记 `glossaryError` 在面板显示，播放不中断。
- 面板：背景 2 行输入 + 「提炼背景并生成词表」；背景摘要直接以 3 行文本框显示（≤300 字，失焦保存，标题旁标注是否进 prompt 与字数）；词表 >8 条默认折叠，展开后 240px 内部滚动，显示条数与字符数；「清空术语」需二次确认（3 秒内再点）。编辑框有独立草稿，1.5s 轮询不会覆盖正在输入的内容。
- 播放中改摘要/词表：pipeline 每段重读 `settings`，下一句生效，不重启采集。

改动文件：`src/config.ts`、`src/translate.ts`（`selectGlossary` / `buildPreparePrompt` / `parseModelPrep` / `Translator.prepareGlossary`）、`src/ui.ts`（`parseBackground` / `parseBrief` / `parseGlossaryPatch` + 四个动作）、`src/controller.ts`、`src/pipeline.ts`、`src/subtitle/protocol.ts`、`src/panel.ts`、`client.js`、`tests/*`。
